# Hackathon

## MongoDB

### Описание

MongoDB поднята в режиме ReplicaSet

Структура:

База данных состоит из трёх идентичных узлов. Каждый узел хранит все данные.
В начале работы выбирается основной узел, выполняющий все записи.
В случае если основной узел падает один из вторичных узлов берёт на себя статус основного.

### Ожидаемое поведение при подъёме

Поднимаем командой
``` shell
docker-compose -f docker.compose.dev.yaml up -d
```

По очереди поднимаются все три базы данных с healthcheck на предыдущую.
Если получаем error message: container <container_name> is unhealthy то у нас что-то упало у предыдущей базы, нужно лезть в её логи.

Далее если три базы по отдельности поднялись запускается контейнер mongo-init.
Он инициализирует реплика-сет скриптом scripts/replica-init.js.

Чтобы посмотреть логи - сразу после запуска пишем:
``` shell
docker logs mongo-init -f
```

Логи достаточно полные, если что-то пойдёт не так вы это увидите.

Дальше заливаем наш датасет в базу. При первом запуске будут загружены все данные, при последующих этот скрипт будет игнорироваться, ваши изменения будут сохраняться между сессиями. Если вы хотитие ресетнуться - удалите папку mongodb/data.

### Как потестить

Подключаемся к mongosh основного узла:
``` shell
docker exec -it mongo1 mongosh
```

Смотрим на существующие базы:
``` shell
show dbs
```
Хотим увидеть три базы - Storage-Base; admin; config; local

Подключаемся к Storage-Base:
``` shell
use Storage-Base
```

Посмотрим на два документа из базы:
``` shell
db.documents.find().limit(2)
```

Должны получить два Json-a, если этот шаг успешен то с основной базой всё нормально.

Для выхода из консоли просто пишем exit.

Теперь сходим к mongosh запасного узла:
``` shell
docker exec -it mongo2 mongosh
```
Прогоните все те же команды что и для основного узла.

Дальше можно ещё поприкалываться, например положить основной узел и проверить что один из запасных станет основным.
``` shell
docker stop mongo1
```
